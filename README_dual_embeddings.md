# Four-source data format and lookup workflow

Entry points: `create_data.py` -> `training.py` or `training_cv.py` -> `models/gat_gcn.py`.
The current single-run notebook is
[notebook/davis-attention-original copy.ipynb](<notebook/davis-attention-original copy.ipynb>).
See [README.md](README.md) for architecture, CV, ensemble, and execution instructions.

## Version 4 dictionary format

Each `data/four_source_embeddings/{dataset}/{train,test}.pt` contains:

| Key | Contents |
| --- | --- |
| `format_version`, `dataset`, `split` | `4`, `davis`/`kiba`, `train`/`test` |
| `ligand_ids`, `protein_ids` | Entity IDs; protein IDs retain their original dataset identities |
| `ligand_id_to_index`, `protein_id_to_index` | Entity ID to table-index mappings |
| `ligand_smiles` | SMILES used for graph construction and embedding identity |
| `ligand_graphs` | Dictionaries with `x [N,78]` and `edge_index [2,E]` |
| `protein_graphs` | Dictionaries with `x [N,41]`, `edge_index [2,E]`, and optional `edge_attr` |
| `ligand_embeddings` | `[L,512]` tensors, retaining every source token including BOS/EOS |
| `protein_embeddings` | `[L,640]` tensors with all residues; the source has no BOS/EOS |
| `protein_embedding_ids` | `prot_<sha256(sequence)>`; may repeat across protein IDs |
| `pairs` | `ligand_index`, `protein_index`, `y`, and `row_id` in original split order |
| `*_embedding_token_lengths` | Actual token lengths without padding or truncation |
| `config` | Dimensions, pooling/truncation conventions, and keys |

Entities are stored once per split; samples store only pair indices. Each file
is self-contained, so entities shared by train/test occur in both files.
Training needs no manifest, prediction CSV, or auxiliary data file. Storage
dtypes match the source; the loader converts features and embeddings to FP32
when building the bank.

## Preparation

`create_data.py` creates v4 directly without sequence-token/CNN data or
intermediate v3 files. CSV splits, labels, and ordering are preserved. When CSVs
are absent, original folds are used; raw DAVIS nM labels are converted to pKd
once, while KIBA affinities remain unchanged. Drug graphs retain complete SMILES,
including salts and isolated nodes.

```bash
python create_data.py --datasets davis kiba --check-only
python create_data.py --datasets davis kiba
```

Existing v4 data is validated and reused without overwriting. New output
directories are published only after both splits are written and checked.
No manifest is generated by default; `--write-pairs-csv` is optional.
Embedding models are not rerun.

## Banks and batches

`FourSourceSplit` validates format, dataset/split identity, entity counts, pairs,
and embeddings. `build_cpu_tables` merges splits and checks that entities with
the same ID have consistent data. Graphs use concatenated node/edge tables;
embeddings use concatenated token tables with offsets. Proteins with equal
sequences share embeddings while keeping their original graph identities.

`DeviceFourSourceStore` copies the bank once to each GPU. `IndexBatches` yields
only pair indices and labels on the primary GPU. `nn.DataParallel` splits these
indices; each replica's `GATnGCN_Model.forward(pair_indices)` calls
`data_store.lookup` on its device. Graph edge offsets are added per sample, and
token batch vectors are separate from graph batch vectors. There is no padding,
CPU graph collation, or whole-bank upload per step.

The bank is not a model parameter or buffer, so model checkpoints exclude data.
The default model pools actual tokens with max+mean in its embedding branches;
protein sequences are not truncated to 1000 residues. Embeddings remain fixed
without fine-tuning Chemformer or ESM.

## Checkpoints

Full checkpoints contain current model weights, Adam state, a separate best
checkpoint, history, and RNG state. Automatic discovery scans
`*checkpoint*.pt`, `*checkpoint*.pth`, `best_model.pt`, and `best_until_epoch_*.pt`;
best/weights-only files are skipped for resume. For other names such as
`model.pt`, use `--resume-path` or the notebook's RESUME_PATH.

Compatibility checks cover model structure, training configuration, and hashes
of IDs, pairs, and labels. Hashes do not reread entire graph/embedding tensors;
use a new output directory rather than resuming when feature banks change.
Model signatures normalize outer class namespaces so equivalent notebook and
Python-module architectures can share checkpoints. Architecture changes, such
as GCN to GAT, remain incompatible.
